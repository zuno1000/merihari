1. 目的と位置づけ

1.1 解決したいこと(ユーザー定義の4目的)

#目的本アプリでの実現手段(要約)対応機能
①YouTube/SNS を「ただ見てしまう」時間を減らし、休憩は休憩・作業は作業とメリハリをつける休憩を理想スケジュールの中に予定として置く(後ろめたさを消す)。SNS/動画を記録するときは「あと何分?」を聞き終了予定を置く。日次レポートで減少を言葉で返すF1, F2, F3, F4
②1日の理想スケジュールを可視化し、時間配分と今日やるべきことを明確にする朝(初回起動時)に今日の理想スケジュールを自動生成し、タイムラインの左レーンに表示。右レーンに実績が積まれるF2, F5
③先延ばし癖の解消「いま」の理想スロットを主役として1つだけ表示し、「始める」=記録開始。とっかかり(最初の5分)・最小単位・未着手の朝の一言・記録ギャップの回収F4, F5
④既存アプリの煩雑さを無くし、アプリを使うこと自体を先延ばししない画面3つ・毎日の操作は全てワンタップ(カテゴリチップ)・設定は初回だけ・記録が抜けても責めない§2 全体

1.2 nokorijikan との関係

後継として新リポジトリ zuno1000/merihari で作り直す。 nokorijikan v0.1(PersonalVault/Projects/nokorijikan/nokorijikan/ptm/)は参照用の資産として残し、以下を流用する:
  • 流用する部品: Google Identity Services の取り回し / freeBusy 取得 / Drive appDataFolder + WebCrypto 暗号化往復 / マージ規則 / 使える時間の計算(freeMs) / 休憩判定(EDF)/ LLM 貼り戻し解析 parseLLM(将来用)
  • 捨てる考え方: 「真実の値は残り見積1つ・作業記録は裏機能」→ merihari は実績タイムラインが主役。ただし「記録を頑張らせない」姿勢は維持する(ワンタップ・ギャップ回収・未記録は責めない)
  • nokorijikan ノートの「評価 A〜E」「ロードマップ」「tangoquest の知見」は本仕様の §11・§14 に取り込み済み

1.3 想定ユーザー・端末

  • ユーザーは本人1人(大学院生: 研究・授業・バイト・就活・英語学習が混在)。公開は GitHub Pages だが他人向けの機能(アカウント、共有)は作らない。
  • 主端末: iPhone Safari → ホーム画面に追加した PWA。副端末: PC(Windows)の Chrome/Edge。両者を Google Drive で同期。
  • 利用シーン: 朝に開いて今日の提案を確認(30秒)/作業の切り替わりにカテゴリをタップ(3秒)/夜にレポートを見る(1分)。

2. 設計方針(変えない約束)

  1. 画面は「ホーム」「タイムライン」「タスク」「設定」の4つだけ。(v0.11: 「今」を「ホーム」に改名)(v0.6 改訂: 当初の3画面から「今日」を「今(いまやること1つ)」と「タイムライン(日付を動かせる)」に分けた)新機能は既存画面の既定動作に溶かすか折りたたみの奥に置く。5つ目のタブは作らない。
  2. 毎日の操作は全部ワンタップで終わる。カテゴリチップ→記録開始。記録の終了は次のチップを押すだけ(連続記録)。時刻入力はフォールバック。
  3. 主役は1つ。「今日」画面の上部ヒーローは「いまの理想スロット」か「いま記録中のもの」のどちらか1つを言葉で言い切る。%・分数などの数字は副文か折りたたみへ。
  4. 記録を頑張らせない・責めない。記録の抜け(ギャップ)は「この時間は?」とワンタップで埋めるか放置できる。レポートは肯定的事実から書き、悪い数字は事実だけ述べる。
  5. Google カレンダーは free/busy のみ。タイトル・場所・参加者は取得しない(スコープ calendar.freebusy)。書き込み権限は要求しない。取得した busy 時間帯は端末内のみに置き、Drive へ送らない。
  6. Drive 同期は端末側でパスフレーズ暗号化。appDataFolder に merihari.enc 1ファイル。パスフレーズは sessionStorage のみ。
  7. 提案・レポートはルールベース。LLM・ML・外部 API は使わない(完全オフラインで動く)。賢さは「移動時間の自動確保」「生活ルーティンの自動除外」「busy の前後配置」「過去7日との比較」などの規則で出す。
  8. 完全無料・サーバー無し。GitHub Pages(Public リポジトリ)+ localStorage + Drive appDataFolder のみ。
  9. 実機 FB 駆動・小刻みリリース。1フェーズ=1〜2セッション、各版を iPhone で数日使ってから次へ(tangoquest/nokorijikan の流儀)。

3. 用語

用語意味
カテゴリ記録・集計の単位。既定: 研究 / 授業 / 英語 / バイト / 就活 / 生活 / 休憩 / SNS・動画 / 移動 / その他。種別として work(作業)・life(生活)・rest(休憩)・drift(ダラダラ: SNS・動画)を持つ。編集可。
記録(entry)「HH:MM〜HH:MM にカテゴリ X(任意でタスク・メモ)」1件。実績レーンに積まれる。
理想スケジュール(plan)その日のブロック列。アプリが生成し、ユーザーがタップで微調整する。理想レーンに表示。
ブロック(block)plan の1要素。種別: busy(カレンダー)/ transit(移動)/ routine(生活)/ habit(毎日の習慣: 英語など)/ task(ToDo の今日の分)/ rest(休憩)/ free(自由)。
作業時間帯曜日ごとの「起きていて作業できる時間帯」(例: 7:00〜23:30)。外側は睡眠として自動除外。
生活ルーティン毎日の固定時間(朝食・昼食・夕食・入浴など)。曜日指定可。plan に routine ブロックとして置かれ、使える時間から引かれる。
移動時間設定した「外出時の片道移動分」(例: 大学 50分)。外出とみなした busy の前後に transit ブロックを自動で置く。
今日の分各 ToDo について「期限までに間に合わせるには今日何時間やるべきか」(EDF 累積から配分)。task ブロックの大きさの元になる。
ギャップ作業時間帯内で記録が無い連続区間(15分以上)。
ベースラインレポートの比較対象。直近7日(今日を除く)のカテゴリ別平均。無ければ比較を省く。

4.1 「今」画面と「タイムライン」画面(v0.6 で分割)

ヒーロー(主役)
状態により1つだけ表示(§6.4 の状態機械)。記録中: 「研究 32分経過」+[終わる][別のことへ]。理想スロット進行中で未記録: 「いま 14:30〜16:00 は 研究」+[始める](=記録開始)[別のことを記録][後ろへ](plan を再配置)。休憩時間: 「休憩していい時間 あと 18分」+[休憩を記録]。生活の時間: 「いまは夕食」。移動中: 「移動中 スマホでできること: ○○」。作業時間外: 「今日はおしまい」+レポート導線。朝の初回: 「今日の予定を組みました」+[OK][調整する]。
カテゴリチップ(＋のシート)
右下の「＋」(記録中は赤い●)でシートを開き、タップで「いまからそのカテゴリ」の記録を開始し、直前の記録中エントリを現在時刻で閉じる。長押し(PC は右クリック)で「時刻を指定」= 開始時刻を選ぶシート。SNS・動画(drift 種別)のチップは押下時に「あと何分?」(10/20/30/決めない)を聞き、終了予定を plan の rest ブロックとして置く(F4-5)。
タイムライン(画面)
縦スクロール、左=理想、右=実績の2レーン。‹ › で前後の日(未来は見通し(仮)、過去は＋で記録追加)。現在時刻に横線。理想ブロックのタップ→[今やる][後ろへ][今日はやらない][長さ −15/+15/+30](v0.7)。予定(busy)または移動のタップ→[在宅/外出]と[移動の長さ −15/−5/+5/+15・15/30/45/60/90分・なし](当日の指定・同じ曜日と時刻で記憶・既定は設定の「移動」)。実績エントリのタップ→[時刻を直す][カテゴリ変更][タスクを紐づけ][メモ][分ける][削除]。ギャップは「この時間は?」のチップで埋める(Phase 5)。
レポート導線
作業時間帯の終了 30 分前から「今日のレポートを見る」を表示。翌日の初回起動時は「昨日のレポート」をヒーローの直下に1行で出す(タップで展開、閉じれば消える)。
鮮度と同期の1行
「予定は 6時間前のもの → 更新」「未同期の変更あり → 同期」をヒーロー下に1行で出す(nokorijikan A1/B2 の反省)。タップ=ユーザー操作なので認証ポップアップが通る。

4.2 「タスク」画面

かんたん追加
名前 + 期限チップ(今日/明日/今週末/来週/2週間後/なし)+ 大きさチップ(30m/1h/3h/8h/20h)の3項目で保存。義務/やりたいは既定「義務」。詳細(最小単位・とっかかり・カテゴリ・繰り返し・メモ)は編集画面。
一覧
「今日の分」(今日やるべき量が正のもの、期限順)→「その他の義務」→「やりたい」→「完了(折りたたみ)」。各行に 今日 Xh / 残 Yh / 期限。チェック=完了。スワイプ無し(iOS で誤操作しやすい)、行タップで詳細。
期限超過の出口
起動時に期限超過かつ残りが正のタスクがあればシートで順に処理: [+1週][残りを半分にして +1週][完了][消す]。処理するまで赤を続けるのではなく、処理させて赤を消す。
繰り返し
「毎週 X 時間」型(終わりのない勉強用)。期限は週の終わりに自動で送り、残り見積を X に戻す。未消化分は繰り越さず「先週 3/5h」と記録だけ残す。(v0.9 実装: plan.rollWeekly ─ periodEnd を持ち、過ぎたら lastWeek{doneMin,hours} を残して remainingH を X に戻す)

4.3 「設定」画面

初回セットアップ(作業時間帯・生活ルーティン・移動・習慣)は3ステップのウィザードで既定値入りの画面を順に確認するだけにする(すべて既定値で「次へ」を3回押せば終わる)。以降は上記ワイヤの項目。Google 連携は「接続する」1ボタン(スコープ2つを一度に同意)。クライアント ID はコードに直書き(上書き欄は折りたたみ内)。

5. 機能仕様

F7. Drive 同期 SHOULD

  • F7-1 スコープ drive.appdata。appDataFolder に merihari.enc(1ファイル)。
  • F7-2 暗号化: PBKDF2(SHA-256, 310,000 回)でパスフレーズから鍵、AES-256-GCM(12 byte IV 毎回ランダム)。パスフレーズは sessionStorage のみ。ファイルに平文のヒント(秘密でない短文)を併置。
  • F7-5 顔認証 / パスキーでの解錠(v0.8・任意): 設定 › Google、またはパスフレーズ入力時のチェックで有効化。WebAuthn の platform authenticator を作り、PRF 拡張の秘密(32 バイト・認証器の中にありユーザー確認なしには出ない)で AES-GCM によりパスフレーズを包んで localStorage に置く(平文は保存しない)。同期時にパスフレーズが無ければ、ユーザー操作の中で get(PRF)→ほどいて sessionStorage へ。PRF 非対応のブラウザでは有効化できず従来どおり。これは §2-6「パスフレーズは sessionStorage のみ」の端末ごとの任意の例外(ユーザー判断・2026-10-11)。
  • F7-3 同期は自然なタップに乗せる: 記録開始/終了・タスク保存・タブ切替時に、未同期の変更があり、トークンとパスフレーズがあり、前回から 5 分以上経っていれば静かに実行。手動ボタンは設定にも置く。
    v0.7 追加(tangoquest 方式): 開いたとき・戻ったときは未同期の変更が無くても同期して他の端末の変更を取り込む。鍵(トークン・パスフレーズ=sessionStorage)が揃っていれば静かに、無ければ最初のタップ(ユーザー操作の中なので認証ポップアップとパスフレーズのシートが出せる)で同期する。取り込みで手元のデータが変わったときだけ画面を描き直し「他の端末の記録を取り込みました」。判断は純関数 autoSyncDecision(silent / gesture / none)。
  • F7-4 マージ: entries/tasks/plans は id ごとに updatedAt の LWW(同点は id の文字列比較で決定的)。削除は tombstone。settings は settingsUpdatedAt。未知キーは保持(前方互換 Object.assign({}, remote, local))。端末データ消去は世代 resetAt で全端末に伝播。merge(a,b)==merge(b,a) をテストで固定。
  • F7-5 同期対象外(端末ローカル): busyCache、トークン、パスフレーズ、UI 状態、当日の外出/在宅上書き。

6. アルゴリズム仕様

6.1 使える時間(nokorijikan freeMs を継承)

usable(day) = window(day)                       // 作業時間帯(曜日別)
            − Σ routine(day)                     // 生活ルーティン
            − Σ busy(day)  − Σ transit(day)      // 予定と移動
            − Σ habit(day) − longRest.min        // 習慣と長い休憩(v0.7: 時刻は固定しない)
workable(day) = usable(day) × ratio               // 作業に回せる割合(既定 0.6)

6.2 plan 生成(擬似コード)

function buildPlan(date, now, settings, busy, tasks, habits) {
  const W = window(date);                           // [start, end]
  let blocks = [];
  // 1. 固定: busy
  for (const b of busy.filter(inDay(date))) blocks.push({type:'busy', ...b});
  // 1b. 睡眠(v0.10): 作業時間帯の外側(0:00〜W.start・W.end〜24:00)から busy を引いた区間を sleep に(予定を優先)
  for (const iv of subtract([[0, W.start], [W.end, 1440]], busy)) blocks.push({type:'sleep', ...iv});
  // 2. 移動: 外出グループの前後(§6.3)
  for (const g of groupOuting(blocks, settings)) {
    blocks.push({type:'transit', start: g.start - settings.transitMin, end: g.start});
    blocks.push({type:'transit', start: g.end, end: g.end + settings.transitMin});
  }
  // 3. 生活ルーティン(重なれば直後の空きへ 15 分刻みでずらす・無理なら省く)
  for (const r of routines(date)) blocks.push(placeOrShift({type:'routine', ...r}, blocks));
  // 4. 毎日の習慣(希望時間帯に、重なれば近い空きへ)
  for (const h of habits) blocks.push(placeOrShift({type:'habit', ...h}, blocks));
  // 5. タスクと休憩(v0.7): 待ち行列 = 今日の分(§6.4・期限順)→ 余った作業枠に期限までにやること(細分化・filler)
  //    休憩は時刻固定ではなく、作業の累計と「続けて作業した分」から置く(F2-6)
  let budget = workable(date) − Σ(紐づく実績);
  queue = [...todayShare(期限順), ...fillers(期限順・残りがある義務)];
  sinceRest = workSinceRest(entries, now);           // 直前まで続けて作業した分(記録から)
  workDone  = 今日の作業種別の記録;  longAt = longRestAt(min(budget, Σ queue.want) + workDone, afterMin);
  for (const slot of freeSlots(blocks, from = max(now, W.start), to = W.end − 30)) {
    if (切れ目 ≥ restMin) sinceRest = 0;
    while (slot に余り) {
      if (!longPlaced && workDone ≥ longAt && longMin が入る) { rest(長い休憩 longMin); sinceRest = 0; continue; }
      head = queue[0]; need = min(head.want, 今日の分なら max(budget, minUnit) else budget) − placed;
      if (need < minUnit) { queue.shift(); continue; }
      if (sinceRest ≥ workMin || workMin − sinceRest < minUnit) { rest(短い休憩 restMin); sinceRest = 0; continue; }
      len = min(need, workMin − sinceRest, slot の余り, longAt − workDone);   // 長い休憩の位置でも区切る
      if (len < minUnit) break;                                              // 次の空きへ(順番は守る)
      blocks.push({type:'task', taskId:head.id, start:cursor, end:cursor+len});
      workDone += len; sinceRest += len; budget −= len;
    }
  }
  shortfall = 今日の分 − 置けた分;                   // ヒーロー副文で事実だけ言う
  // 6. 残りは free。作業時間帯の最後 30 分は free 固定
  return fillFree(blocks, W);
}

再計画(F2-7)は from = now として 5〜6 だけやり直す。1〜4 は当日中は固定(ユーザーの手動編集は pinned フラグで保護)。

6.3 外出判定(busy にタイトルが無い前提での規則)

  1. 設定「予定がある日は外出扱い」(既定 ON)。ON のとき、日中(作業時間帯の開始+1h 〜 18:00)にある 45 分以上の busy は外出候補。
  2. 外出候補同士の間隔が「片道移動 × 2」未満なら同じグループ(間に帰らない)。グループの最初の前・最後の後にのみ transit。
  3. ユーザーがその日の busy をタップして「在宅」にすれば、そのグループから除外(当日限りの上書き outingOverride[date][busyId]、端末ローカル)。
  4. 将来: 曜日ごとの既定(「月・水は大学」)を設定に足せるようにしておく(MAY)。

6.4 今日の分(EDF 配分・nokorijikan から継承)

義務タスクを期限順に並べ、累積で
  A_i = Σ_{d ≤ deadline_i} workable(d)      // 期限までに使える時間
  R_i = Σ_{j ≤ i} remaining_j               // 期限までに終えるべき残り
  需要 ρ_i = R_i / A_i
今日の分: todayMin_i = remaining_i × workable(today) / A_i を基本に、
  ρ_i ≥ 1 のタスクは切り捨てず前倒し(足りない分は「このままでは足りません」と赤で事実だけ)。
休憩判定(F4-6): Σ todayMin − Σ 今日の紐づき実績 ≤ 0 → 「今日はおしまい」。

6.5 レポート文の生成規則

候補文(肯定)条件優先度
「{カテゴリ}は理想より {Δ} 多く進められました」work 種別で 実績 − 理想 ≥ 15 分1(Δ 大きい順)
「{drift カテゴリ}は先週の平均より {Δ} 減りました」drift 種別で ベースライン − 実績 ≥ 15 分1
「{カテゴリ}は理想どおりできました」|実績 − 理想| < 15 分 かつ 理想 ≥ 30 分2
「休憩は予定どおり {時刻} に取れました」rest ブロックと rest エントリが 30 分以上重なる2
「作業は合計 {h} でした(先週平均 {h'})」work 合計 ≥ ベースライン3
「{n} 日続けて記録できています」連続日数 ≥ 24
「記録できた時間 {h}。それだけで十分です」上のどれも無いとき(必ず 1 文は出す)フォールバック

改善点(最大 2 文・事実だけ): 「{カテゴリ}は今日は入りませんでした」(理想 ≥ 30 分で実績 0)/「{drift}は {h} でした(先週平均 {h'})」(増えたとき)/「未記録が {h} ありました」(≥ 1h)。明日への一言: 期限 3 日以内の未着手タスクを 1 件だけ。

6.6 作業に回せる割合の校正(週1回)

毎日 ledger[date] = {usableMin, workMin} を自動記録(入力不要)。週に1回(日曜または設定曜日)の初回起動で、直近 7 日の Σ workMin / Σ usableMin が設定 ratio と 10 ポイント以上ずれていれば「先週は使える時間の 42% が作業でした。割合を 60%→45% にしますか?」をワンタップ提案。理想のスケジュールで終わらないための唯一の自動校正。

8.2 脅威と対策

懸念対策
カレンダーの内容漏えいfree/busy のみ。タイトル等を取得できるスコープを要求しない。busy は端末内のみ・Drive へ送らない。

公開リポジトリデータはコードに含まれない(端末+暗号化 Drive のみ)。クライアント ID 以外の秘密は無い。コミット前に個人情報(氏名・予定)が入らないよう、サンプルデータは架空にする。
依存ライブラリGIS(accounts.google.com/gsi/client)以外の外部スクリプトを使わない。npm 依存ゼロ。
多端末の競合LWW+tombstone+決定的同点規則。マージの対称性をテストで固定。
