2. 設計方針(変えない約束)

  1. 画面は「ホーム」「タイムライン」「タスク」「お金」「日記」の5タブ(並びは v0.20・FB ⑥)+設定(ホーム右上の歯車)。(v0.18/v0.19 改訂・ユーザー指示: 設定はタブから外し日記をタブに、タブ中央の ＋ を「お金」に。記録の ＋ はホーム左上とタイムライン右上 → v0.24 でタイムライン右下の丸ボタンだけに。これ以上タブは増やさない)(v0.11: 「今」を「ホーム」に改名)(v0.6 改訂: 当初の3画面から「今日」を「今(いまやること1つ)」と「タイムライン(日付を動かせる)」に分けた)新機能は既存画面の既定動作に溶かすか折りたたみの奥に置く。5つ目のタブは作らない。(v0.28: ホームは 円と棒だけ。タスク・予定・ふり返りへの導線と気合のカードはホームから外し、同期は設定の先頭と歯車の赤い点に)
  2. 毎日の操作は全部ワンタップで終わる。カテゴリチップ→記録開始。記録の終了は次のチップを押すだけ(連続記録)。時刻入力はフォールバック。
  3. 主役は1つ。ホームの主役は「きょうの内訳」(1日の円)。その上に「記録中のもの」か「◯分 未記録。何をしていた?」のどちらか 1 行だけ(v0.15。v0.14 までは「いまの理想スロット」)。%・分数などの数字は副文か折りたたみへ。
  4. 記録を頑張らせない・責めない。記録の抜け(ギャップ)は「この時間は?」とワンタップで埋めるか放置できる。レポートは肯定的事実から書き、悪い数字は事実だけ述べる。
  5. Google カレンダーは free/busy のみ。タイトル・場所・参加者は取得しない(スコープ calendar.freebusy)。書き込み権限は要求しない。取得した busy 時間帯は端末内のみに置き、Drive へ送らない。
  6. Drive 同期は端末側でパスフレーズ暗号化。appDataFolder に merihari.enc 1ファイル。パスフレーズは sessionStorage のみ。
  7. 提案・レポートはルールベース。LLM・ML・外部 API は使わない(完全オフラインで動く)。(v0.26 注・2026-10-28 決定: 天気と服装の提案(§11 Phase 19)は Open-Meteo(無料・キー不要)を「設定で地域を登録した人だけ」の任意機能として足す。F11 と同じ扱いで、既定は無効・オフラインでも他は動く)(v0.21 注: F11「AI に頼む」はアプリの外=iOS ショートカットの「モデルを使用」に文を渡すだけで、アプリ内に AI は無く、無効が既定。この約束の例外ではなく、約束を保ったまま「やりたい人だけ足す」経路)(v0.32 注: F16 作業用 BGM はカタログを同梱して選ぶだけで通信は無く、♪ のタップでリンクとして YouTube を開く。推薦はルールベース・既定は無効)(v0.34 注: F17 キャッチアップは GitHub Actions が毎朝作る同じサイトの 1 ファイル(data/feed.json)を読むだけで、記事はリンクとして外のサイトを開く(アプリの外)。選び方はルールベース(気になる語・新しさ・ジャンルを回す)・既定は無効)賢さは「最後の記録の終わり〜いま を先に入れておく」「予定の時間に何をしたかを曜日・時刻で覚える」「期限から逆算した今日の量」「過去7日との比較」などの規則で出す(v0.15。移動の自動確保・ルーティンの除外・busy の前後配置は理想スケジュールと共に廃止)。
  8. 完全無料・サーバー無し。GitHub Pages(Public リポジトリ)+ localStorage + Drive appDataFolder のみ。
  9. 実機 FB 駆動・小刻みリリース。1フェーズ=1〜2セッション、各版を iPhone で数日使ってから次へ(tangoquest/nokorijikan の流儀)。

3. 用語

v0.15: 「理想スケジュール(plan)」「ブロック」「生活ルーティン」「移動時間」は廃止(データの plans は同期のため残すが作らない)。「今日の分」は「目安」に改め、残り ÷ 期限までの日数(今日を含む)とする。新しい用語: 目安=タスクごとの量(期限つき: 今日の分 / 毎日 ◯分 / 毎週 ◯時間 / やりたいこと: 目安なし・最後にふれた日)。予定の記憶(settings.busyMemory)=予定の時間に記録したカテゴリを曜日×開始15分丸めで覚え、次からその予定の候補にする。

用語意味
カテゴリ記録・集計の単位。既定: 研究 / 授業 / 英語 / バイト / 就活 / 生活 / 休憩 / SNS・動画 / 移動 / その他。種別として work(作業)・life(生活)・rest(休憩)・drift(ダラダラ: SNS・動画)を持つ。編集可。
記録(entry)「HH:MM〜HH:MM にカテゴリ X(任意でタスク・メモ)」1件。実績レーンに積まれる。
理想スケジュール(plan)その日のブロック列。アプリが生成し、ユーザーがタップで微調整する。理想レーンに表示。
ブロック(block)plan の1要素。種別: busy(カレンダー)/ transit(移動)/ routine(生活)/ habit(毎日の習慣: 英語など)/ task(ToDo の今日の分)/ rest(休憩)/ free(自由)。
作業時間帯曜日ごとの「起きていて作業できる時間帯」(例: 7:00〜23:30)。外側は睡眠として自動除外。
生活ルーティン毎日の固定時間(朝食・昼食・夕食・入浴など)。曜日指定可。plan に routine ブロックとして置かれ、使える時間から引かれる。
移動時間設定した「外出時の片道移動分」(例: 大学 50分)。外出とみなした busy の前後に transit ブロックを自動で置く。
今日の分各 ToDo について「期限までに間に合わせるには今日何時間やるべきか」(EDF 累積から配分)。task ブロックの大きさの元になる。
ギャップ作業時間帯内で記録が無い連続区間(15分以上)。
ベースラインレポートの比較対象。直近7日(今日を除く)のカテゴリ別平均。無ければ比較を省く。

6.1 使える時間(nokorijikan freeMs を継承)

usable(day) = window(day)                       // 作業時間帯(曜日別)
            − Σ routine(day)                     // 生活ルーティン
            − Σ busy(day)  − Σ transit(day)      // 予定と移動
            − Σ habit(day) − longRest.min        // 習慣と長い休憩(v0.7: 時刻は固定しない)
workable(day) = usable(day) × ratio               // 作業に回せる割合(既定 0.6)

6.2 plan 生成(擬似コード)

function buildPlan(date, now, settings, busy, tasks, habits) {
  const W = window(date);                           // [start, end]
  let blocks = [];
  // 1. 固定: busy
  for (const b of busy.filter(inDay(date))) blocks.push({type:'busy', ...b});
  // 1b. 睡眠(v0.10): 作業時間帯の外側(0:00〜W.start・W.end〜24:00)から busy を引いた区間を sleep に(予定を優先)
  for (const iv of subtract([[0, W.start], [W.end, 1440]], busy)) blocks.push({type:'sleep', ...iv});
  // 2. 移動: 外出グループの前後(§6.3)
  for (const g of groupOuting(blocks, settings)) {
    blocks.push({type:'transit', start: g.start - settings.transitMin, end: g.start});
    blocks.push({type:'transit', start: g.end, end: g.end + settings.transitMin});
  }
  // 3. 生活ルーティン(重なれば直後の空きへ 15 分刻みでずらす・無理なら省く)
  for (const r of routines(date)) blocks.push(placeOrShift({type:'routine', ...r}, blocks));
  // 4. 毎日の習慣(希望時間帯に、重なれば近い空きへ)
  for (const h of habits) blocks.push(placeOrShift({type:'habit', ...h}, blocks));
  // 5. タスクと休憩(v0.7): 待ち行列 = 今日の分(§6.4・期限順)→ 余った作業枠に期限までにやること(細分化・filler)
  //    休憩は時刻固定ではなく、作業の累計と「続けて作業した分」から置く(F2-6)
  let budget = workable(date) − Σ(紐づく実績);
  queue = [...todayShare(期限順), ...fillers(期限順・残りがある義務)];
  sinceRest = workSinceRest(entries, now);           // 直前まで続けて作業した分(記録から)
  workDone  = 今日の作業種別の記録;  longAt = longRestAt(min(budget, Σ queue.want) + workDone, afterMin);
  for (const slot of freeSlots(blocks, from = max(now, W.start), to = W.end − 30)) {
    if (切れ目 ≥ restMin) sinceRest = 0;
    while (slot に余り) {
      if (!longPlaced && workDone ≥ longAt && longMin が入る) { rest(長い休憩 longMin); sinceRest = 0; continue; }
      head = queue[0]; need = min(head.want, 今日の分なら max(budget, minUnit) else budget) − placed;
      if (need < minUnit) { queue.shift(); continue; }
      if (sinceRest ≥ workMin || workMin − sinceRest < minUnit) { rest(短い休憩 restMin); sinceRest = 0; continue; }
      len = min(need, workMin − sinceRest, slot の余り, longAt − workDone);   // 長い休憩の位置でも区切る
      if (len < minUnit) break;                                              // 次の空きへ(順番は守る)
      blocks.push({type:'task', taskId:head.id, start:cursor, end:cursor+len});
      workDone += len; sinceRest += len; budget −= len;
    }
  }
  shortfall = 今日の分 − 置けた分;                   // ヒーロー副文で事実だけ言う
  // 6. 残りは free。作業時間帯の最後 30 分は free 固定
  return fillFree(blocks, W);
}

6.3 外出判定(busy にタイトルが無い前提での規則)

  1. 設定「予定がある日は外出扱い」(既定 ON)。ON のとき、日中(作業時間帯の開始+1h 〜 18:00)にある 45 分以上の busy は外出候補。

  3. ユーザーがその日の busy をタップして「在宅」にすれば、そのグループから除外(当日限りの上書き outingOverride[date][busyId]、端末ローカル)。

6.4 今日の分(EDF 配分・nokorijikan から継承)

義務タスクを期限順に並べ、累積で
  A_i = Σ_{d ≤ deadline_i} workable(d)      // 期限までに使える時間
  R_i = Σ_{j ≤ i} remaining_j               // 期限までに終えるべき残り
  需要 ρ_i = R_i / A_i
今日の分: todayMin_i = remaining_i × workable(today) / A_i を基本に、
  ρ_i ≥ 1 のタスクは切り捨てず前倒し(足りない分は「このままでは足りません」と赤で事実だけ)。
休憩判定(F4-6): Σ todayMin − Σ 今日の紐づき実績 ≤ 0 → 「今日はおしまい」。

6.6 作業に回せる割合の校正(週1回)

公開リポジトリデータはコードに含まれない(端末+暗号化 Drive のみ)。クライアント ID 以外の秘密は無い。コミット前に個人情報(氏名・予定)が入らないよう、サンプルデータは架空にする。
依存ライブラリGIS(accounts.google.com/gsi/client)以外の外部スクリプトを使わない。npm 依存ゼロ。
多端末の競合LWW+tombstone+決定的同点規則。マージの対称性をテストで固定。v0.25(レビュー A-2): アップロード直前に Drive の modifiedTime を取り直し、取得時と違えば(別の端末が先に上げた)取り込み直してから上げる(最大 3 回)。

12. 見送り・やらないこと(理由つき)

  • SNS/動画の自動計測: Web アプリからスクリーンタイムは取れない。自己申告(チップ)+ギャップ回収で代替。iOS ショートカット「YouTube を開いたら ?log=sns を開く」を README に案内(MAY)。
  • YouTube の 1 日の再生時間をレポートに出す(2026-10-28・ユーザー FB): YouTube Data API v3 には視聴履歴・再生時間を返す API が無い(watchHistory は 2016 年に廃止。Google Takeout の書き出しは手動で、日次には使えない)。iOS のスクリーンタイムも Web から読めない。これまでどおり自己申告(「SNS・動画」のチップ・?log=sns のショートカット)で、レポートの「ダラダラ」に数える。
  • 定時プッシュ通知: サーバー無しの iOS PWA では不可。ショートカット/時計で代替。
  • カレンダーのタイトル取得・書き込み: プライバシー方針。
  • LLM/ML による提案: ルールベースで足りる・説明可能性・コスト。将来 nokorijikan のコピペ方式を足す余地だけ残す(parseLLM を流用可能)。
  • ドラッグ&ドロップでの plan 編集: iOS で誤操作しやすい。タップのメニューで足りる。
  • 4 つ目のタブ・統計ダッシュボード: 画面が増えると「どれで何をするか」が分からなくなる。レポートは「今日」画面の中。
  • 複数ユーザー・共有・アカウント: 個人用。
  • パスフレーズを持ち続けない設計(レビュー B-1: 固定 salt + 非抽出 CryptoKey を IndexedDB に・あるいはモジュール内変数だけ)(2026-10-27): §2-6「パスフレーズは sessionStorage のみ」の約束と、同期ファイルの形式(毎回ランダム salt)を変えることになる。XSS 対策(textContent のみ・CSP)で現実的な危険は低いと評価されているので見送り。必要になったら v1.x で形式ごと移行する。
  • localStorage → IndexedDB(レビュー A-4)(2026-10-27): 全データが 1 キー(目安 5MB)。設定 › データ に「データの大きさ」を出して様子を見る。数年分で近づいたら移す。
  • リポジトリの private 化: GH Pages 無料枠は Public 限定。データはコードに含まれない。
